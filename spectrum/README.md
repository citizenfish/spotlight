# Spectrum port (Z80)

The first decisions are made and the toolchain is proven end to end; see *The
port begins* in the vault for the reasoning and the figures behind each one.

- **Target: 48K, no paging.** Pinned with `DEVICE ZXSPECTRUM48` so a build that
  outgrows it fails loudly rather than quietly paging. Audio is the beeper.
- **Assembler: sjasmplus v1.21.0**, built from source:

  ```sh
  git clone --depth 1 --branch v1.21.0 https://github.com/z00m128/sjasmplus.git
  cd sjasmplus && git submodule update --init --recursive && make
  cp sjasmplus ~/.local/bin/
  ```

  The submodule step is not optional -- without it the build fails on
  `LuaBridge/LuaBridge.h`. There is no Homebrew formula.

  Then `make` in this directory builds `build/spotlight.bin`, and `make tables`
  regenerates the two committed tables from `assets/`. Point `SJASMPLUS` at the
  binary if it is not on `~/.local/bin`.

- **Tests: SkoolKit's `Simulator`, headless in `pytest`** (`pip install
  skoolkit`, already in the prototype's venv). It hands back the 6,912-byte
  screen and an exact T-state count, so the port is held to the same
  byte-identity discipline as the Pygame prototype: the screen compared against
  `core.screen.Screen`, and the frame compared against `ENTITY_CEILING`
  (32,832 T-states).

  `Simulator` holds registers in a list of 30 **by index**: `A` 0, `F` 1,
  `SP` 12, `I` 14, `R` 15, **`PC` 24**, **`T` 25**. Memory is a plain list of
  65,536 ints.

Still to decide: the loader and tape image format (`bin2tap` ships with SkoolKit
and sjasmplus writes tapes directly, so it is a build-script line once there is
something worth loading), and the memory map, which is written after the first
slice runs rather than guessed before it.

`src/` holds assembly source -- `bitmaps.asm` and `logo.asm` are generated by
`tools/bitmaps.py` and committed, and a test regenerates and compares them byte
for byte. `build/` holds output and is gitignored.
