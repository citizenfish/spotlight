; floor.txt
;
; The stipple: how the game tells you a cell is floor at all.
;
; A lit cell with no pixels set is just black -- ink on black paper with no ink
; drawn -- so without a stipple, light reveals *objects* but never its own
; shape, and the player cannot tell how far their spotlight reaches.
;
; **The two densities are the contrast step the palette cannot give.** LIT and
; DIM differ by only 255 against 215 on one channel, which is nearly invisible
; on a moving sprite; four dots against one is not. So the fade is carried by
; how much of a cell is drawn, not by hue, and it will carry the same way on a
; Spectrum where the two levels are BRIGHT and not-BRIGHT of one ink.
;
; **The densities are tuned and are not to be redrawn** (issue #51 said so of
; the dots, and issue #71 kept the densities while redrawing the arrangement).
; They decide how much of a room the player is told about, and the dim one is
; deliberately one dot in sixty-four -- ground you are remembering rather than
; seeing. Changing how many dots a cell has is a gameplay change, not an art
; tidy-up. Where the dots *sit* is drawing, and it is what changed below.
;
; **The arrangement is a noise tile over four cells** (issue #71, from *The
; light trail* in the vault). Until then the lit floor was one 8x8 pattern,
; four dots on a four-pixel pitch, and every lit region -- wedge, disc or
; trail -- read as a rectangle of dots whatever its outline was, because a
; lattice has rows for the eye to run along: a set pixel had a neighbour four
; to its right eight times in ten. The Great Escape's gravel, measured, was a
; 32-pixel repeat with nothing lining up at eight or sixteen, and one set pixel
; in twenty had a twin eight to its right. So the floor is now a 32x32 tile --
; the sixteen FLOOR_LIT blocks below in reading order, cell 00 top-left and
; cell 15 bottom-right -- with exactly four dots in every cell, no two dots
; adjacent anywhere in the tile (wrapping included), and the lattice gone. A
; cell at play-area (cx, cy) wears block (cy & 3) * 4 + (cx & 3). Not zero at
; the cell pitch, measured: eight of the sixty-four dots have a twin eight
; pixels to the right and three have one eight below, against fifty of
; sixty-four on the lattice.
;
; **The dim tile is the lit tile thinned.** Each FLOOR_DIM block keeps the
; first of its lit block's four dots in reading order -- top row first, left
; to right -- and clears the other three, so lit -> dim is a thinning and not
; a shuffle: the one dot you remember is one of the four you saw.
;
; The 32x32 tile, whole, so it can be read as the picture it is. The blocks
; below are cut from it and the suite checks that they reassemble to it:

; Two things elsewhere are measured against these dots and would have to be
; re-measured if the densities moved:
;
;   * the player's foot bar is five pixels of solid ink because the lit
;     stipple swallows anything narrower (issue #49, and see
;     assets/sprites/player.txt) -- and a cell of four dots, none of them
;     adjacent, cannot put an unbroken run of five anywhere, so the mark
;     survives the noise tile as it survived the lattice;
;   * `test_spike_tiles` checks that the returns drawn in a doorway leave the
;     lit stipple showing through, because a lit cell with nothing in it reads
;     as an unlit one. A *painted* cell -- a sign, a shout -- is the exception
;     since issue #71: it draws no stipple at all and the glyph sits on black,
;     because the noise tile does not fall between the letters the way the
;     lattice happened to (`E:X:I:T` in the mock), and paint hides texture on
;     the floor as it already did on a wall.
;
; These blocks were the oldest bitmaps in the game and the last art still
; declared as hex in drawing code; they came here so that the answer to *what
; does a floor look like* is a file and not a Python module, and so that the
; drift test guards them like every other bitmap.
